# 作り方（1本を通す手順）

```bash
npm start                      # http://localhost:8787
npm run new -- my-topic "第2審 — 〇〇は本当か"
# cases/my-topic.json を書く（docs/TONE-AND-MANNER.md を先に読む）
npm run check                  # 当日事故る間違いを検査
npm run build                  # dist/my-topic.html（1枚・オフラインで動く）
node tools/smoke.mjs cases/my-topic.json   # 実際のブラウザで頭から最後まで通す
```

---

## 1. エッセンスから始める

書き始める前に、この3つだけ埋めます。**ここが埋まらないうちは JSON を触らない。**

1. **聴衆がいま持っている誤解は何か**（＝証言になる）
2. **それは何と衝突するか**（＝ムジュン。今日の核）
3. **終わったとき何ができるようになっていてほしいか**（＝takeaways）

`prompts/case-director.md` を AI に渡すと、ここを対話で詰めてから
トンマナの提案つきでケースJSONを書かせられます。

## 2. 検査する

`npm run check` が見るもの：

- **まだ配っていない証拠をつきつけさせていないか**（本番で詰む最多の事故）
- ムジュンのない証言がないか（永久ループになる）
- `correct:true` のない選択肢がないか（進めなくなる）
- `who` が cast にいるか、`bg` / `sfx` が実在するか
- セリフが長すぎないか（テキストボックスから溢れる）
- 箇条書きが6行以上ないか、takeaways があるか
- 発表者ノートが3箇所以上あるか

## 3. 実際に通す

`node tools/smoke.mjs` は **本物のブラウザにキーを打ち込んで**頭から最後まで通し、
`dist/shots/` にスクリーンショットを残します。
「たぶん動く」と「動いた」は別なので、登壇前に必ず通してください。

## 4. 持ち運ぶ

`npm run build` で `dist/<名前>.html` が1枚できます。
CSS・JS・ケース・`assets/` の画像まで全部インラインなので、
**USBに入れても、会場のネットが死んでも、`file://` で開いても動きます。**

登壇当日はこれをデスクトップに置いてダブルクリック。これが一番事故りません。

## 外から見たい / スマホで確認したい

```bash
npm run build:artifact        # dist/<名前>.artifact.html
```

doctype と `<html>/<head>/<body>` を持たない本体だけの版が出ます。
これを Claude の Artifact として publish すると、URL が1本もらえて
スマホでも会場のPCでも開けます（外部参照ゼロなので CSP に当たりません）。

---

## 数字の賞味期限

デモケース（`demo-quantum.json`）の数字には出典と年を入れてあります。
**登壇前に必ず最新を確認してください。** 古い数字を法廷で自信満々に読み上げるのは、
このテンプレートで一番まずい負け方です。

`meta.sourcesNote` に、いつ確認したかを書き残す欄があります。

---

## 画像を使う

`assets/` に置いて、`"assets/foo.png"` と書きます。
ビルド時に data URI としてインラインされます（`tools/build.mjs`）。

外部URL（`https://...`）は `check.mjs` が警告します。会場のネットは死ぬので。

## 当日の運用

| 場面 | やること |
|---|---|
| 開始前 | `F` で全画面、`H` で発表者ノート、`T` でタイマー |
| 進行 | クリッカーの `→` だけ。証拠つきつけのときだけ手元で数字キー |
| 時間が押した | `Esc` → 目次から先の章へ飛ぶ（証拠は自動で揃います） |
| 客席に振る | `choice` の画面で挙手させてから押す |
| 最後 | 判決の1枚で20秒黙って、写真を撮らせる |
